# Claude Code の指示文の提言

Claude Code に読ませる指示文（CLAUDE.md・スキル・メモリ）を、Claude が前提を誤らずに判断できる形にするための提言です。作者が AI を使うときの考え方と、そこから導いた指示文の雛形・スキル、指示文の作り方をまとめてあります。

## 考え方

この提言は、確認を怠ること、前提を考えずに進めることを Claude にやめさせるための規則を集めたものです。規則の多くは、作者が持っている考え方と前提から導いています。その全体は `考え方.md` にあり、特に大事にしているのは次の4つです（`考え方.md` で＊を付けた節）。

- 思考は与えられた前提から決定的に行われる（1）
- 判定は会話の外に委ねる（4.1.1）
- 押されて変わったAIの考えを正しさの裏付けにしない（4.2）
- 常に完璧なもののみを求めて進める（5.1）

作者の環境や好みから来た規則もあり、どれがそうかは `理由.md` にあります。`考え方.md` には、Claude にさせることのほかに、指示文で縛っても Claude がしてしまうので利用者が気をつけること（4.2 など）も書いてあります。

## 使い方

この提言は、全部をそのまま取り入れなければならないものではありません。まず `考え方.md` を読んでください。この考え方が気に入るなら、提言を見て、次のように使うといいでしょう。

- 指示文の作り方（`skills/instruction-review/SKILL.md`）や、指示文そのもの（`CLAUDE.template.md` と同梱のスキル）を、自分の指示文に取り入れる。
- 手元の Claude Code に、今の指示文をこの提言に照らして見直させ、直した案を出させる（下の「指示文を見直させるとき」。任意）。

雛形を取り入れるときは、「利用者の環境と特性」の欄を自分で埋めるか、Claude に `INTRO.md` の手順4で埋めさせてください。

## 中身

- `考え方.md`：作者が持っている考え方と前提。規則の多くはここから導いています。まずこれを読み、提言を取り入れるかを判断する材料にしてください。
- `INTRO.md`：指示文を見直させるときに Claude が読む導入の手順。今の指示文を読み、元のファイルの控えを取り、この提言に照らして見直し、変更後の全文で案を出し、利用者の承認を取ってから当てる。
- `CLAUDE.template.md`：全体の CLAUDE.md に常に入れておく規則の雛形。利用者の環境と特性の欄は、`INTRO.md` の手順で見直させるときは Claude が埋めます。入っているランタイムのように Claude が調べられる事実は調べ、利用者の使い方や決まりのように利用者にしか分からないことだけを利用者に聞きます。
- `理由.md`：雛形と instruction-review・pc-environment の規則ごとに、なぜその規則があるかを書いたもの。一般の理由、作者の環境から来た理由（どういう環境なら成り立つか）、作者の好みを分けて書いてあります。見直させるときは、Claude が指示文に書かない理由を置く場所へ写します。合わない規則を外すか決めるときの材料にしてください。
- `skills/instruction-review/SKILL.md`：指示文を書く・見直すときの基準のスキル。
- `skills/search-procedure/SKILL.md`：やりたいことを構造化して、何を探すべきかを決めてから探す手順のスキル。
- `skills/pc-environment/SKILL.md`：その PC の環境の事実と、ツールを作るときの決まりを書くスキルの雛形。全体の CLAUDE.md に常に入れておくほどではないが、特定の作業で知らないと誤る事実を、ここに集めます。見直させるときは Claude が調べて埋め、利用者にしか分からないことは利用者に聞きます。
- `hooks/claude-file-watch-hooks/`：Claude が読んだファイルを、利用者やほかのツールが書き換えたとき、その差分を次の発言のときに Claude に知らせるフック。Claude が古い中身を前提に判断するのを防ぎます。Windows 専用です。公開先は https://gist.github.com/noileg/0b5e85b6628907d1f2c79d4920d05303 で、ここには2026年10月時点のソース（Go）と exe をそのまま入れてあります。入れ方は同じフォルダの `README.ja.md` にあります。
- `hooks/claude-file-show-hook/`：Claude が応答に目印の1行（`[[見せる: パス#見出し]]` など）を書くと、画面の上でだけ、その行をファイルの該当部分に差し替えるフック。Claude が中身を打ち直さないので、写し間違いが起きず、中身が Claude のコンテキストにも入りません。公開先は https://github.com/noileg/claude-file-show-hook （MIT）で、ここには2026年10月時点のソース（Go）と Windows 用の exe をそのまま入れてあります。入れ方は同じフォルダの `README.ja.md` にあります。

## 指示文を見直させるとき（任意）

1. このリポジトリを手元に置きます（`git clone https://github.com/noileg/claude-instructions`）。
2. Claude Code で、次のように頼みます。

```
<このリポジトリのパス>/INTRO.md を読んで、その手順で私の指示文を見直してください。
```

URL を渡して読ませるのではなく、手元に置いたファイルを読ませてください。Web から読ませると、ページの要約が渡り、文面がそのまま届かないことがあります。

見直しの途中で、Claude から次のことを聞かれることがあります。先に決めておくと早く進みます。

- 書き換える前の控えを置く場所。
- 応答とコード中のコメントに使う言語。
- ファイルを置いてはいけない場所や、移動・削除の前に確認が要る場所があれば、その場所。
- 自分で書くと決めている提出物（志願書類、大学のレポートなど）があるか。
- Claude に自分の文書の箇所を指してもらうなら、その文書を書くエディタに行番号が出るか。
- Claude に知っておいてほしい、指示の書き方や話し方の癖があれば、その癖。
- 使ってほしくない Claude Code の機能があれば、その機能。
- セッションの終わりに Claude にレポートを書かせるなら、その場所。
- 指示文に書かない理由・経緯を置く場所。
- 過去の同じ取り組みを探す手段（台帳や索引など）があるか。
- Claude に新しいツールを入れさせるなら、その入れ方（管理者権限が要るか、パッケージマネージャが使えるか）。
- 同梱のフックとスキルを入れるか。
- 今の指示文のうち、提言と食い違う規則を、提言に合わせるか残すか。

## 注意

- 見直しの手順（`INTRO.md`）では、書き換える前に元のファイルの控えを取り、ファイルごとに変更後の全文を見せて承認を取ってから当てます。
- `CLAUDE.template.md` と instruction-review スキルの文面は、利用者ごとに言い換えずに使う前提です。合わない項目は、Claude と相談して、利用者が決めたものだけ外すか書き換えてください。
- 雛形とスキルは、2026年10月時点の Claude Code の既定と比べて書いています。版が変わると、既定の文面も変わります。
