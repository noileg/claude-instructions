# claude-file-show-hook

English: [README.md](README.md)

Claude Code の会話窓に、ファイルの中身を表示する hook。Claude が中身を打ち直すことも、
Claude のコンテキストに中身が入ることもない。

## なぜ作ったか

Claude Code にファイル（下書きや仕様書の一節など）を見せてもらうとき、Claude は中身を
応答として打ち直すか、ツールでファイルを出力するかのどちらかをする。打ち直せば出力トークンを
使い、写し間違いも起こりうる。ツールで出せば、中身がまるごとコンテキストに入る。別のエディタで
開くと、会話窓から離れることになる。

この hook は、表示専用の `MessageDisplay` イベントを使う。hook が返した文は、画面の表示だけを
変える。Claude は目印を1行書き、hook がその行を、画面の上でだけ、目印が指すファイルの該当部分に
差し替える。記録（transcript）と Claude のコンテキストに残るのは、目印の1行だけになる。

## 見え方

Claude の応答に、次のように書かれていたとする。

```
スケジュールの節はこうなっています。

[[見せる: C:\work\plan.md#スケジュール]]

2つ目を変えますか？
```

画面では次のように見える（`-lang ja` のとき。既定の英語では区切りの行が begin / end になる）。

```
スケジュールの節はこうなっています。

──── ここから：`C:\work\plan.md#スケジュール` ────

## スケジュール
- 金曜までに下書き
- 月曜にレビュー

──── ここまで ────

2つ目を変えますか？
```

中身は Markdown として描画され、表も表になる。区切りの行は、ファイルから写した部分の始まりと
終わりを示す。

## 目印の書き方

目印は、行頭から始まり、その行に他の文字がないときだけ働く。

| 見せる範囲 | 目印 |
|---|---|
| ファイル全体 | `[[見せる: パス]]` |
| 見出しの節 | `[[見せる: パス#見出し]]` |
| 行範囲（1始まり、両端を含む） | `[[見せる: パス:10-40]]` |
| コードブロックで囲んで原文のまま | 末尾に ` \| 囲む` を付ける（例：`[[見せる: パス#見出し \| 囲む]]`） |

`[[show: …]]` と ` | raw` も、`-lang` の設定にかかわらず同じように働く。

- 見出しの節は、見出しの文字列が完全に一致する見出しから、同じか上位の次の見出しの手前まで。
  コードブロックの中の `#` 行は見出しと見なさない。`パス##見出し` のように見出しの `#` を付けても
  指定できる。同じ文字列の見出しが2つ以上あれば失敗になる。
- 相対パスは、セッションの作業ディレクトリから解決する。`~/` はホームディレクトリを指す。
- 書式の説明などで、働かせずに目印を書きたいときは、行頭に空白を入れる。

## 導入

いちばん簡単なのは、この README を Claude Code に渡して導入を頼むことである。自動モードの
Claude Code は、自分の設定ファイルの書き換えを断ることがある。その場合は手順2を手で行う。

1. [Releases](https://github.com/noileg/claude-file-show-hook/releases) から
   `claude-file-show-hook.exe` を取ってきて（または下の手順でビルドして）、好きな場所
   （例：`~/.claude/hooks/`）に置く。
2. `~/.claude/settings.json` の `hooks` に、`MessageDisplay` の項目を足す。`command` は exe の
   絶対パスにする。

   ```json
   "MessageDisplay": [
     {
       "hooks": [
         {
           "type": "command",
           "command": "C:\\Users\\you\\.claude\\hooks\\claude-file-show-hook.exe",
           "args": ["-lang", "ja"]
         }
       ]
     }
   ]
   ```

   `-lang ja` は、区切りの行と失敗の表示を日本語にする。外すと英語になる。
3. 自分の `CLAUDE.md`（全プロジェクトに効かせるなら `~/.claude/CLAUDE.md`）に、目印の書き方を
   Claude に教える文を足す。例：

   ```markdown
   ファイルの中身（またはその一部）を見せるときは、打ち直さず、ツールで出力もせず、応答に単独の行で
   `[[見せる: 絶対パス#見出し]]` と書く（行範囲は `絶対パス:10-40`、全体はパスだけ、原文のままなら
   末尾に ` | 囲む`）。MessageDisplay の hook が画面の上でだけその行をファイルの中身に差し替える。
   中身はあなた（Claude）には見えない。書式を説明するために書くときは、行頭に空白を入れる。
   ```

## 失敗したとき

ファイルを見せられないときは、目印の行が `[見せる失敗: 理由]` に置き換わる（理由は
`ファイルがない`、`見出しがない`、`同名の見出しが2個ある`、`行範囲が範囲外` など）。目印の行を
そのまま残すと、hook が入っていないときと見分けがつかないので、失敗は必ず表示する。

秘密情報が入りやすいファイルは、名前だけで判定して見せない。対象は `.env`・`.env.*`・`*.pem`・
`*.key`・`*.pfx`・`id_rsa*`・`id_ed25519*`・`id_ecdsa*`・`.git-credentials`・`.netrc` と、
`.ssh`・`.aws`・`.gnupg` の配下。シンボリックリンクは、リンク先でも判定する。目印は Claude の
出力から出てくるので、Claude が何を書かされても、こうしたファイルが画面に出ないようにしている。

5MB を超えるファイルと、UTF-8 でないファイルは失敗として表示する。UTF-8 の BOM は落とす。

## 制限

- 中身が出るのは、応答が最初に表示されたときだけである。`--resume` でセッションを開き直すと、
  過去の応答には中身ではなく目印の行が出る。見たいときは、Claude に目印を書き直してもらう。
  同じセッションの中でスクロールして戻る分には、中身は出たままになる。
- verbose モードでは、元の目印の行が出る。
- Claude Code 2.1.152 以降が必要（`MessageDisplay` が追加された版）。
- Windows 11 の Claude Code 2.1.309 で、約4.9万字（1250行）が切り詰めなしで出ること、Markdown の
  表が表として描画されることを確かめた。それより長いものは試していない。
- ビルド済みの exe は Windows（amd64）用。コードは素の Go なので macOS と Linux でもビルドできる
  はずだが、試していない。
- Claude Code は、表示する行のまとまりごとに hook を起動し、終わるまで表示を待つ。1回の起動は、
  Windows でプロセスの起動込み約10ミリ秒かかる。

## ビルド

Go 1.27 以降が必要。

```
go build -trimpath -o claude-file-show-hook.exe .
go test ./...
```

`-trimpath` を付けるのは、ビルドした環境のファイルパスを exe に残さないため。
