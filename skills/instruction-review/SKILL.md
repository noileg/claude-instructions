## 前提

Claude の判断は、指示と前提から決定的に導かれる。判断に使わない文は、導く過程に混ざってノイズになり、事実でない前提は、正しく導いても誤った結論を出す。見直しの目的は、判断に使わないものを除き、誤った前提を直し、欠けた前提を足すこと。

## 各記述に当てる3つの問い

- 問1：消したら、導かれる行動が変わるか。変わらないなら書かない。
- 問2：前提は今も事実か。違えば確かめて直す。足りなければ調べて足し、調べて分からなければ利用者に聞く。
- 問3：その場所で常に要るか。要らなければ移す。

## 問1から出てくること

- 経緯・日付・発言者・事故・回数は指示文に書かない。理由は、その指示を守るべき場面を Claude が判断するのに要る分だけ前提として書き、それ以外は指示文とは別の退避先（全体の CLAUDE.md の「利用者の環境と特性」に書いた、指示文に書かない理由・経緯の置き場所）に残す。
- 判断に使っていたものは、消さずに指示か前提に書き直す。
- 禁止は、禁止そのものが目的のとき（前提から導けず、禁止すること自体が利用者の目的であるとき）と、破ると取り返しがつかないときだけ書く。
- 否定された側（「A ではなく B」の A、「〇〇ではない」の〇〇）は書かず、する側だけを書く。例：「A ではなく B を使う」は「B を使う」と書く。
- 書かなくても外れない振る舞いは書かない。
- Claude が考えることではない、ほかの仕組みの内部の動きは書かない。
- Claude Code の既定（システムプロンプトとツールの説明）と同じ強さ・同じ方法で言っていることは書かない。ただし取り返しがつかないものは残す。既定より強く言っているもの、別の方法を示しているものは、既定では足りなかったことの表れなので残す。

## 問2で確かめること

- パス・設定・バージョン・ツールの有無のように、Claude が確かめられるものは、コマンドで確かめ、どう確かめたかを記録する。
- 利用者の習慣・好み・環境の使い方のように、利用者にしか分からないものは、原文を見せて利用者に聞く。
- 一部の状況でしか成り立たないのに、いつもそうだと書かれている前提は、成り立つ状況に限る。ただし、利用者がその状況を既定だとするなら限らない。
- 前提が偽と分かった指示は、利用者が決めたことかもしれないので、消す前に利用者に聞く。

## 主語

- 行動する主体を名指しする。「自分」「あなた」は、書き手（利用者）とも読み手（Claude）とも読めるので使わない。
- 主語の無い文を「Claude の行動を指す」と一括で定めない。利用者の行動を言っている文まで、Claude が Claude の行動として実行してしまう。主語が明確でない文は、1文ずつ主語を書く。

## 問3の置き場所

- どのプロジェクトでも守るもの、会話のどこで要るか予測できないもの、前提として常に持っておくもの：全体の CLAUDE.md（`~/.claude/CLAUDE.md`）。
- どのプロジェクトでも成り立つが、特定の作業をするときにしか要らないもの：全体のスキル（`~/.claude/skills/`）。利用者が作ったツールや、その PC に固有のもののうち特定の作業でしか要らないものもここに置き、どのプロジェクトからも使えるようにする。Claude Code がシステムプロンプトで渡さず、常に要る PC の事実（例：Python を実行するときに要る環境変数）は、全体の CLAUDE.md に置く。OS やシェルのように Claude Code が渡しているものは書かない。
- 特定のプロジェクトにしか関係しないもの：そのプロジェクトの CLAUDE.md か README。
- auto memory には置かない。確認を経ずに Claude が書いたものが、次のセッションの前提になるため。

## 見直しの進め方

- 書き換える前に、元のファイルを日付つきのフォルダへコピーして控えを取る。
- 指摘は、1件ごとに、元の文の引用、どの問い・どの項目に当たったか、変更した項目の変更後の全文を出す。「ここをこう変えた」だけでなく、項目の全文を添える。
- 件数が多いときは、まず指摘の一覧を出して利用者の返事を待ち、次に数件の例を出して返事を待ち、そのあと全体を出す。数件の例は、直したい箇所だけに偏らせず、ある程度無作為に選ぶ。
- Claude が判断したことには理由を添える。利用者は理由が無いと許可を出せない。
- 当てるのは、ファイルごとに変更後のファイル全体を利用者に見せ、承認を得てからにする。承認はその時点の案に対するもので、案が変わったら改めて承認を取る。
- 当てたあと、元の文にあった、判断に使う前提が消えていないかを確かめる。
- 消した文そのもの、その文がもともとあった理由、今回消した理由は、控えのフォルダに見直しの記録として残す。
- 利用者の意図は、要約でなく利用者の発言の原文に当たって拾う。
